# ジョブ {#jobs}

Jobs ページは全員のページです。文書を印刷するフォームと、自分が見られるジョブがあります。

## 文書を印刷する {#print}

ノードとファイルを選び、必要ならジョブの名前（指定しなければファイル名）を入れて、Print を押します。並ぶノードは自分が送れるものです。共有のもの、自分のグループのもの、自分のものです（[スコープ](roles.md#scopes)）。ジョブはそのノードで受け取られ、管理者が引いたエッジに沿って流れます。どこへ行き、何が起きたかは、フォームの下の一覧と [Topology](topology.md#view) ページで分かります。

ノードが受け取れるものは種類によります（[ペイロードの種類](flow.md#kinds)）。プリンタ、ディスプレイ、キュー、インボックスは文書を受け取ります。PDF、Office 文書（Word、Excel、PowerPoint）、画像、`.bdf` など、コンバータが読める形式です。受け取ったときに `.bdf` 文書に変換されます。テンプレートノードはデータ（JSON、YAML、CSV、Excel ブック）を受け取って帳票を埋めます。変換ノードはファイルをそのまま受け取ります。エンドポイントは設定どおりのものを受け取ります。ノードが受け取れない形式のファイルは拒否され、ページがそう伝えます。

## 自分のジョブ {#list}

一覧には、自分が送ったジョブと、自分のグループのノードに送られたジョブが並びます（[ジョブを見られる人](roles.md#who-sees)）。管理者と監査者はすべてのジョブを見ます。Refresh で読み直します。

| 列 | |
|---|---|
| No. | ジョブの番号。`#12` のように、どのページでも、監査ログでも、アーカイブでも同じ番号です |
| Name | ジョブの名前。マウスを重ねると、受け取ったもの（種類と形式）とジョブのメタデータが見えます |
| Sent to | 送り手が送った先のノード |
| Sent by | 誰が送ったか。マネージャーが確認したものです。サインインした人、アプリ、トークン、エンドポイント、匿名のいずれかです。送り手が別の人の名前を名乗ったとき（`?user=`、IPP の requesting-user-name）は、その後ろに「(as …)」と表示します。名乗っただけで、確認はしていません |
| Group | そのジョブを見られるメンバーのグループ。送った時点でのノードの所有者グループです |
| Received | 受け取った日時 |
| State | [状態](#states)を参照 |
| Route | レグです。ジョブが到達した各ノードとそこで起きたことを `node:state` の形で並べ、クラスが選んだメンバーやフィルタが一致したルールを括弧で、エラーを `!` の後ろに示します |

**Document** はジョブの `.bdf` 文書をダウンロードします。受け取ったもの、またはテンプレートノードや変換ノードが最後に作ったものです（[ペイロード](flow.md#payloads)）。

**Reprint** は文書をもう一度、自分の新しいジョブとして、元と同じノードに送ります。Shift を押しながらクリックすると、代わりに上のフォームで選んだノードに送ります。新しいジョブは元のジョブの送り手のメタデータを引き継ぎます。送り先のノードに送れる人でなければなりません。

**Cancel** は送り手と管理者ができます。グループのメンバーはジョブを見るだけです。ジョブは、終わっていない間、またはディスプレイボードで伝票がまだ開いている間に取り消せます。取り消すと、伝票はボードから消え、インボックスの項目は破棄され、まだ送っていない配送は取り下げられます。プリンタが印刷し終えたものはそのままです。

## 状態 {#states}

ジョブの状態はレグから決まります。

| 状態 | |
|---|---|
| `processing` | 配送が未完です。プリンタ、アーカイブ、テンプレートや変換のステップがジョブを持っていて、まだ終わっていません |
| `held` | インボックスが留めていて、ほかに未完のものはありません |
| `completed` | すべてのノードが受け取りました。表示、印刷、アーカイブ、保持、送り出し、または破棄済みです |
| `canceled` | 送り手か管理者が取り消しました |
| `aborted` | 配送が最終的に失敗しました。再試行をすべて終えたか、再試行では直らない失敗がすぐに起きたかです（[配送](inboxes.md#deliveries)）。またはアサートがジョブを拒否しました |

レグの状態は、ノードがジョブに対してしたことです。

| レグ | ノード | |
|---|---|---|
| `routed` | キュー、クラス、フィルタ、アサート、ブランチ、エンドポイント、CUPS サーバー | エッジに沿って先へ送りました。ブランチではレグに枝が記されます |
| `shown` | ディスプレイ | デバイスに伝票として表示しました。ジョブが取り消されると `canceled` です |
| `held`、`released`、`discarded` | インボックス | 留めた。人が送り出した。人が破棄した、または取り消しで破棄された |
| `pending`、`done`、`failed`、`canceled` | プリンタ、アーカイブ、テンプレート、変換 | 配送です。待っているか送信中。完了。諦めた。取り消しで取り下げられた |
| `kept` | シンク | シンクが保持する最新のものの 1 つです |
| `listed` | エクスポート | 所有者の下に一覧されました。レグに所有者が記されます（[エクスポート](exports.md)） |
| `dropped` | フィルタ、ブランチ | 一致するルールやケースがなく、otherwise や default もありません |
| `refused` | アサート | ジョブがチェックを通りませんでした。どれかはエラーにあります（[チェック](flow.md#checks)）。ジョブが送られたノードの直後なら、送り手は拒否されています |
| `error` | 任意 | ノードがジョブを受け取れませんでした。理由はエラーにあります。受け取れない種類のペイロード、なくなったノードなどです |

終わったジョブは既定で 14 日間保存されます（運用者の `job_keep`）。文書は、何かがまだ表示している間は残ります。その後に削除されます。
