# ノードの種類 {#node-kinds}

すべてのノードに種類があり、種類ごとの設定があります。入口（エンドポイントと CUPS サーバー）は外から文書とデータを受け取ります。キュー、クラス、フィルタ、インボックスは振り分けます。テンプレートノードと変換ノードは文書を作ります。ディスプレイ、プリンタ、アーカイブ、シンクはジョブの行き着く先です。アーカイブの後ろのエクスポートは、アプリケーションや人がジョブを取りに来る場所です。どの種類のノードも `/ipp/print/<name>` の IPP プリンタでもあります（[IPP](entries.md#ipp)）。サイドバーで「No IPP printer」に印を付けたノード（`no_ipp`）は IPP プリンタになりません。前のノードからだけ届き、IPP のクライアントの一覧にも出ません。

## すべてのノード {#common}

| 設定 | |
|---|---|
| Name | ノードの名前（[名前・題名・説明](topology.md#names)） |
| Title | 名前の下に表示します |
| Description（`description`） | ノードが何のためにあるかのメモ。1000 文字まで。最初の数行がキャンバスのノードの中に、全文がサイドバーに出ます |
| Scope、Owner | ページからノードに送れる人と、そのジョブが誰のものか。`shared`（サインインした全員）、`group` で所有者にグループ、`personal` で所有者に本人のメールアドレス（[ノードのスコープ](roles.md#scopes)） |
| On error（`on_error`） | このノードの送りや段が最終的に失敗したとき、届いたものを持ってジョブが向かうノード。たとえば[通知](#notify)ノード。無ければ全体の既定（`docflow.on_error`）へ、それも無ければジョブはここで中止します（[失敗の行き先](#on-error)） |

サイドバーの 1 行が、ノードが受け取るものと送り出すものを示します（[ペイロードの種類](flow.md#kinds)）。

## エンドポイント {#endpoint}

アプリケーション向けの REST の入口です。`POST /in/<name>` にエンドポイント自身のキーを添えると、ボディの文書、またはテンプレートノード向けのデータを受け取り、ジョブを `to` のすべてのノードへ送ります。リクエストは[エンドポイント](entries.md#endpoints)にあります。

| 設定 | |
|---|---|
| Forwards to（`to`） | 選んだすべてのノードがジョブを受け取ります |
| Accepts（`accept`） | `file`: 文書（既定）。`data`: JSON、YAML、CSV、Excel ブック、Parquet ファイル。後ろのテンプレートノード向けです |
| Sends on（`output`） | 文書をどう送り出すか。`bdf` は作った `.bdf`（既定）、`file` は受け取ったままのファイル。後ろの変換ノードやアーカイブ向けです |
| Formats（`formats`） | 受け取る形式。コンバータの名前で指定します（`pdf`、`docx`、`image`、`csv`、`bdf`、`json`、`yaml` ……）。空ならすべて受け取ります。ほかの形式のファイルは拒否され（415）、拒否は監査ログに残ります |
| Metadata（`meta`） | エンドポイントが受け取るすべてのジョブに加えるキー。送り手のキーより優先します（[メタデータ](flow.md#metadata)） |
| Port（`port`） | プロセス自身のポート。そこへの POST はすべてこのエンドポイント宛てです（サーバーレスでは使えません） |
| Apps allowed（`apps`） | キーのほかに、自前の資格情報でここへ送れるアプリ（[アプリ](entries.md#apps)） |

キーはエンドポイントを作ったときとキーを回したときに 1 度だけ表示されます。マネージャーが保存するのはそのハッシュだけです。

## CUPS サーバー {#cups}

コンピュータや業務システム向けの IPP の入口です。プロセス自身のポートで動く CUPS サーバーで、プリンタはノード自身の 1 台です。`lpstat -h <host>:<port> -p` で一覧でき、コンピュータは `ipp://<host>:<port>/printers/<name>` に印刷し、受け取ったものは `to` のすべてのノードへ進みます。設定は [CUPS サーバーノード](entries.md#cups)にあります。

| 設定 | |
|---|---|
| Forwards to（`to`） | 選んだすべてのノードが、ここに印刷されたものを受け取ります |
| Port（`port`） | サーバーが待ち受けるポート（サーバーレスでは使えません） |
| TLS（`tls_cert`、`tls_key`） | 証明書とキーのファイル。`ipps` になります。なければ平文の `ipp` です |
| Accepts、Sends on、Formats、Metadata | エンドポイントと同じです。Print-Job リクエストのジョブ属性はメタデータになります。`ipp.media`、`ipp.copies` …… |

## キュー {#queue}

ジョブを `to` のすべてのノードへ送ります。ほかのノードの前に置く仮想プリンタで、複数あれば分岐です。到達したものをそのまま送ります。

| 設定 | |
|---|---|
| Forwards to（`to`） | ノード |

## クラス {#class}

ジョブを `members` の 1 つに送ります。順番に（`round-robin`、既定）、または先頭に（`failover`）です。ジョブを受け取らないメンバー（届かないプリンタ）は、次の試行で次のメンバーに飛ばされます。

| 設定 | |
|---|---|
| Members（`members`） | ノード。順番どおり |
| Policy（`policy`） | `round-robin` または `failover` |

## フィルタ {#filter}

ルールでジョブを先へ送ります。ジョブに一致する最初のルールが、そのルールのノードへ送ります。どのルールにも一致しないジョブは `otherwise` へ行くか、なければそこで終わります（`dropped`）。到達したものをそのまま送ります。ルールが見るものは[フィルタのルール](flow.md#rules)にあります。

| 設定 | |
|---|---|
| Rules（`rules`） | 順番どおり。一致条件（名前、ユーザー、形式、ページ数、メタデータ、ペイロードの種類）とノード |
| Otherwise（`otherwise`） | どのルールにも一致しないジョブの行き先 |

## テンプレート {#template}

到達したデータでテンプレートの 1 つを埋め、帳票を `.bdf` 文書として `to` のすべてのノードへ送ります。受け取るのはデータだけです。JSON、YAML、CSV、Excel ブックです。テンプレートとデータは[テンプレートとデータ](templates.md)にあります。

| 設定 | |
|---|---|
| Forwards to（`to`） | 埋めた帳票の行き先 |
| The data as it came to（`original`） | 到達したままのデータの行き先。帳票と同じトレースが付きます（[原本とトレース](flow.md#traces)） |
| Template（`template`） | 埋めるテンプレート。id で指定します |
| Template from（`template_from`） | 代わりに、値がテンプレートを指すメタデータのキー（送り手の `doc-type`） |
| List name（`list_name`） | レコードの一覧（CSV ファイル、シート、JSON の配列）であるデータがテンプレートの中で持つ名前。既定はファイル名 |
| Strict（`strict`） | テンプレートが引く名前のないデータを拒否します |

このステップは配送と同じように行われます。経路が決まった直後にプロセスが、またはティックが行います。テンプレートがない、データが読めないときは再試行せず、最終的な失敗になります（[配送](inboxes.md#deliveries)）。

## 変換 {#convert}

受け取ったままのファイル（PDF、Office 文書、画像）から `.bdf` 文書を作り、`to` のすべてのノードへ送ります。`.bdf` はそのまま送ります。JSON と YAML にはそれ自体の文書がなく（テンプレートを埋めてください）、CSV と Parquet ファイルにはまだ印刷するページがありません。このステップは配送と同じように行われます。

| 設定 | |
|---|---|
| Forwards to（`to`） | 文書の行き先 |
| The file as it came to（`original`） | 到達したままのファイルの行き先。文書と同じトレースが付きます（[原本とトレース](flow.md#traces)） |
| Formats（`formats`） | 変換する形式。空ならコンバータが読めるすべてを変換します |

## インボックス {#inbox}

人が Admin → Inboxes でノードへ送り出すか破棄するまで、ジョブを留めます（[インボックス](inboxes.md#inboxes)）。送り出した項目と破棄した項目は `keep` の間表示されます。

| 設定 | |
|---|---|
| Releases to（`to`） | 項目を送り出せるノード。空ならどのノードにも |
| Keep（`keep`） | 終わった項目を表示しておく期間（14 日） |

## ディスプレイ {#display}

ディスプレイに登録したデバイス（拠点のタブレット）にジョブを伝票として表示し、`fallback.after` の間に誰も開かなかったもの、またはデバイスが 1 台もつながっていない間のすべての未開封の伝票を、フォールバックプリンタで紙に印刷します。受け取るのは `.bdf` 文書だけです。デバイスとボードは[ディスプレイボードとデバイス](displays.md)にあります。

| 設定 | |
|---|---|
| Fallback printer、after（`fallback`） | プリンタと、未開封の伝票が印刷されるまでの時間。0 ならデバイスがつながっていない間だけ |
| Keep（`keep`） | 完了または取り消した伝票をボードに残す期間（14 日） |
| Offline after（`offline_after`） | デバイスが黙っていても接続中とみなす時間（2 分） |

## プリンタ {#printer}

マネージャーがネットワーク越しに届くプリンタで、ジョブを紙に印刷します。受け取るのは `.bdf` 文書だけです。失敗した印刷は再試行されます（[配送](inboxes.md#deliveries)）。

| 設定 | |
|---|---|
| URL（`url`） | `ipp://` または `ipps://`（IPP プリンタ、または CUPS サーバーのキュー: `ipp://host:631/printers/<queue>`）、`socket://host:9100`、`lpd://host/queue` |
| Route（`route`） | ジョブがプリンタに届く経路です。`direct` はマネージャーが送ります（既定）。`branch`（拠点の `bdf printd` が取りに来る）はまだありません。そのプリンタへの配送は失敗します |
| Preview（`preview`） | 偽プリンタファームの API 上のこのプリンタの URL（`tools/fakeprinter`）。偽プリンタが受け取ったものを、ファームが読み戻したとおりにノードの横に表示します |

## アーカイブ {#archive}

到達したもの（`.bdf` 文書、または受け取ったままのファイルやデータ）と、ジョブの JSON の記録（メタデータ、ペイロード、レグ）をストアに書きます。各オブジェクトは 1 度だけで、マネージャーが変更も削除もしません。バケットに既定の保持期間（S3 Object Lock）を与えれば、誰も変えられない監査証跡になります。書き終えると、ジョブは `to` のすべてのノードへ進みます。そこにあるエクスポートがジョブを一覧に載せます（[エクスポート](exports.md)）。

| 設定 | |
|---|---|
| Store（`store`） | 文書のストア。`bbolt:path`、`s3://bucket?region=…`、`r2://bucket?endpoint=…`、`gcs://bucket` |
| Collection（`collection`） | オブジェクトの接頭辞。既定は `archive-<name>` |
| Forwards to（`to`） | 書き終えたジョブが進むノード。エクスポートです |

## シンク {#sink}

到達した最新の文書を保持し、トポロジーで見られるようにします。最初のページはノードに、すべてのページはサイドバーに表示されます。新しいものが来ると古いものは消えます。プリンタやデバイスなしで文書を確かめる場所です。エンドポイントや CUPS サーバーを設定している間、その後ろに置きます。

| 設定 | |
|---|---|
| Latest（`latest`） | 保持する数（10） |

## エクスポート {#export}

前にあるアーカイブが書いたものを一覧し、アプリケーションや人が `GET /out/<name>` で取りに来られるようにします。各エントリは、メタデータが示す所有者の下に並びます。アーカイブを通らずに届く経路は拒否され、ここへ印刷することはできません。誰が何を読むか、バックエンドとフロントエンドは[エクスポート](exports.md)にあります。

| 設定 | |
|---|---|
| Owner's key（`by`） | 文書が誰のものかを値で示すメタデータキー。送り手が与えた顧客の id やメールアドレスです。空なら、人はもともとジョブで見られたものを読みます |
| Subject（`subject`） | 人の何を所有者と比べるか。`email`（既定）、`sub`、`id`、`group`（[誰の文書か](exports.md#owners)） |
| Fields（`fields`） | 一覧のエントリに写すメタデータキー。読み手が表示や選択に使います（16 個まで） |
| Entries（`entries`） | 全員分と所有者ごとに一覧する最新のエントリ数（1000）。それより古いエントリも、ジョブの番号で読めます |
| Apps allowed（`apps`） | トークンですべてのエントリを読むバックエンド（スコープ `export`）。フロントエンドは本人として読むので、載せる必要はありません |

## S3 Trigger {#s3-trigger}

バケットに置かれたオブジェクトの入口です。バケットを待ち受けはしません。S3 のイベントを EventBridge のルール（API destination）か Lambda に送り、そこからオブジェクトの参照を `POST /in/<name>` にノードのキーを添えて送ります。キーはエンドポイントと同じく作られ、ローテーションできます。ボディは `{"bucket": …, "key": …}`、S3 の通知（`Records`、オブジェクト 1 つ）、EventBridge のイベント（`detail`）のどれかです。ノードが自分でオブジェクトを読み、ジョブはメタデータに `s3.bucket` と `s3.key` を持って先へ進みます。

| 設定 | |
|---|---|
| Bucket（`url`） | `s3://bucket?region=…`。AWS 以外のサービス（MinIO、R2）には `&endpoint=…` |
| Credential（`credential`） | `access-key:secret-key`、または `:session-token` 付き。無ければ AWS の既定（環境変数、ロール）（[資格](#credentials)） |
| Prefix（`path`） | 受け取るキーの接頭辞。それ以外のキーや別のバケットは拒否します（403） |
| Forwards to、Accepts、Sends on、Formats、Metadata | エンドポイントと同じ |

## 描画 {#render}

届いた `.bdf` 文書を PDF に、または 1 ページを PNG 画像（150 dpi）に描きます。BDF のビューアを持たない相手（メールの読み手、Web サービス）へ送る出口の前に置きます。描いたファイルは任意のファイルとして `to` へ進みます。配信と同じく裏で行います。

| 設定 | |
|---|---|
| Forwards to（`to`） | ファイルを送るノード |
| Format（`format`） | `pdf`（既定）か `png`。SVG はまだありません |
| Page（`page`） | PNG にするページ（1） |

## 通知 {#notify}

ジョブが通ったことを知らせ、届いたものを `to` があればそこへ送ります。失敗は [on_error](#on-error) の辺からエラーと一緒に届きます。文書は送りません。

| 設定 | |
|---|---|
| Via（`via`） | `slack`：Incoming Webhook。URL を資格に置きます。`mail`：メール。メールノードと同じ設定で、添付はありません。`http`：JSON（`text`、`job`、`name`、`node`、`error`、`error_node`、`meta`）を `url` に POST。資格は Authorization に使います |
| Text（`text`） | 知らせる文。`{{meta.<key>}}` が使えます。既定ではジョブとノード、失敗ならノードとエラー |
| Forwards to（`to`） | ジョブが続けて向かうノード |

## メール（SMTP） {#smtp}

届いたものを添付してメールで送ります。Message-ID は配信の ID で、再試行しても変わりません。

| 設定 | |
|---|---|
| Server（`url`） | `smtp://host:587`（サーバーが出せば STARTTLS）か `smtps://host:465` |
| Credential（`credential`） | `user:password`。TLS の上か、同じマシンにだけ渡します |
| From、Recipients、Subject、Text（`from`、`recipients`、`mail_subject`、`text`） | メールの中身。`{{meta.<key>}}` が使えます |

## S3 {#s3}

届いたものをバケットに 1 度だけ書き、後は見ません。既にあるオブジェクトは書いたものとみなします。記録と一緒に残す必要があるものは[アーカイブ](#archive)へ送ります。

| 設定 | |
|---|---|
| Bucket（`url`）、Credential（`credential`） | S3 Trigger と同じ |
| Key（`path`） | `{{meta.<key>}}` が使えます。既定は `{{meta.$job}}/{{meta.$name}}`。値は接頭辞の外へ出られません（`..` と先頭の `/` を落とします） |

## HTTP {#http}

届いたものをリクエストのボディとして Web サービスへ送ります。ジョブのメタデータは `X-Meta-*` ヘッダに、配信の ID は `Idempotency-Key` になります。別の Docflow へ送るなら、URL を相手の `/in/<node>` に、資格をアプリのトークンにします。`.bdf` はそのまま届きます。408、429、5xx は再試行し、それ以外の応答は最終的な失敗です。

| 設定 | |
|---|---|
| URL（`url`） | `http(s)://…`。`{{meta.<key>}}` が使えます（値は URL 用にエスケープ） |
| Method（`method`） | `POST`（既定）か `PUT` |
| Headers（`headers`） | 追加のヘッダ。`{{meta.<key>}}` が使えます |
| Credential（`credential`） | Authorization。トークンなら Bearer で送り、`Basic …` のように方式付きならそのまま |

これらの種類にはサイドバーの専用の欄がなく、設定は JSON の欄に書きます。

## 失敗の行き先 {#on-error}

送りや段が最終的に失敗すると（拒否、テンプレートが無い、再試行の最後）、ジョブはノードの `on_error` の辺（破線）を通り、届いたものと、次のノードから見える `$error` と `$error_node` を持って進みます。辺の無いノードの失敗は全体の既定（`docflow.on_error`、`DOCFLOW_ON_ERROR`）へ向かいます。ただし既に失敗の道にいるジョブは既定へ送りません。通知ノードの失敗が自分を知らせ続けないためです。どちらも無ければ、ジョブはそこで中止します。どの場合もジョブは中止です。辺は知らせるためのもので、直すものではありません。

## 資格と `{{meta.<key>}}` {#credentials}

ノードは資格を名前で指します（`credential`）。秘密そのものはノードと一緒に保存されません。値は環境変数 `DOCFLOW_CRED_<name>`（`-` は `_`）、無ければ `docflow.credential_dir` の中のファイル `<name>` です。出口と通知ノードの設定には `{{meta.<key>}}` が使えます。式はありません。使える鍵はジョブのメタデータ（[メタデータ](flow.md#metadata)）と、`$node`、`$delivery`、`$name`（文書の名前）、`$error`、`$error_node` です。無い鍵は空になります。ヘッダは改行を、キーは `..` を落とします。出口はどれも少なくとも 1 度送ります。結果の分からない送りは同じ配信の ID でもう 1 度送るので、相手はそれで見分けます。
