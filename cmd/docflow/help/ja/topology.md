# トポロジー {#topology}

トポロジーは文書が流れるネットワークです。あらゆる種類のノードと、その間のエッジです。サインインした全員の 1 つのページ、Topology にあります。役割 topology を持つ人はそこで編集し、それ以外の人は見て、送れるところに印刷します。バーの Admin も、管理者ページの Topology タブも、同じページに行きます。

## キャンバス {#canvas}

キャンバスは、管理者が置いた位置にノードを描きます。ノードは白い箱で、役割の色の題名バー、種類のアイコン、名前、その下に `[種類]` と題名、説明の最初の数行があります。

| 役割 | 種類 |
|---|---|
| Source | エンドポイント、CUPS サーバー |
| Control flow | キュー、クラス、インボックス |
| Filter | フィルタ |
| Transform | テンプレート、変換 |
| Sink | ディスプレイ、プリンタ、アーカイブ、シンク、HTTP (pull) |

ポートとエッジは流れるもので色分けされます（[ペイロードの種類](flow.md#kinds)）。青は `.bdf` 文書、緑はデータ、琥珀色は受け取ったままのファイル、シアンは保管されたファイル（インボックスかアーカイブから HTTP (pull) へ）、紫は複数の種類です。まだ型の決まっていないポートは中抜きの破線です。キュー、クラス、フィルタ、インボックスは最初のエッジの種類を受け取ります。赤い破線のエッジは、もうつながっていません（[壊れたエッジ](flow.md#broken)）。エクスポートには外へ向かう破線の矢印があります。一覧したものをアプリケーションや人が取りに来ることを表します。キャンバスの下の凡例が色を説明します。

キャンバスには、自分が見られるジョブ（自分のものと自分のグループのもの。管理者は全員のもの）の動きが流れます。

- 各ノードの数。インボックスに留まった項目、ディスプレイで開いている伝票、プリンタやアーカイブで待つ配送、失敗した配送、エクスポートが一覧しているエントリ、直近 1 時間にそのノードへ到達したジョブです。
- エッジを走る点。直近 10 分のレグです。

背景をドラッグすると移動、ホイールかピンチで拡大縮小、Fit でトポロジー全体を収めます。ページは数秒ごとにマネージャーをポーリングします。題名の横のバッジが、動きの最終更新か、マネージャーに届かないことを示します。

## 見る {#view}

役割 topology がなければ、このページは見るだけです。ノードをクリックすると、サイドバーにその説明、そこにある自分のジョブの数、送り先、受け取るものと送り出すもの、そして次のものが出ます。

- **Print here**: そのノードに送れるとき（[ノードのスコープ](roles.md#scopes)）。ファイルとジョブ名を指定します。[Jobs](jobs.md#print) と同じです。送れなければ「You may not print here」と出ます。
- **Jobs here**: そのノードに送られたか到達した自分のジョブ。状態、送り手、日時、経路が並びます。Document でダウンロードし、Reprint here でこのノードに自分の新しいジョブとして送り直します。

シンクなら保持している最新の文書、エクスポートならそこに一覧されている自分が読めるエントリも出ます（[HTTP (pull)](exports.md)）。

## エディタ {#editor}

役割 topology があれば、同じページがエディタです。キャンバスと、選んだノードのサイドバーがあり、上に管理者のタブが並びます。

- **+ Add a node** で種類のパレットが開きます。種類は Source、Control（役割の Control flow と Filter）、Convert（Transform）、Sink の 4 つの見出しに分けてあります。1 つ選ぶと新しいノードがキャンバスに現れ、サイドバーが開きます。名前と設定を入れて Add を押します。Escape で取りやめます。
- **ノードをクリック**するとサイドバーに開きます。設定と、そこにあるもの（[ノードのサイドバー](#sidebar)）です。Save でノードを書き込み、Delete か Delete キーで削除します。ほかのノードが送り先にしているノードは削除できません。先にエッジを外します。
- **ノードをドラッグ**すると動きます。ノードを描く位置は、ノード自体とは別に、全員のものとして保存されます（レイアウト）。
- **ノードの右側のポートから別のノードへドラッグ**するとつながります。ドラッグ中は、エッジが運ぶものを受け取らないノードが薄くなり、その上では線が赤くなって理由が出ます。受け取るノードではそのポートに吸い付きます。受け取らないノードに落とすと、サーバーに問い合わせる前に拒否されます。エッジはノードの `to`（キュー、エンドポイント、CUPS サーバー、インボックス、テンプレートノード、変換ノード、アーカイブ）、`members`（クラス）、`otherwise`（フィルタ。ルールのノードはルールの中で設定します）に加わるか、フォールバックプリンタになります（ディスプレイ）。エッジをクリックすると、確認のうえで外せます。
- Zoom、Fit、Refresh。

ノードは Save のときに検査されます。名前で参照するノードが存在すること、名前がほかの種類のものでないこと、ノードへ戻る経路がないこと、新しいエッジが先のノードの受け取らない種類のペイロードを持ち込まないことです。持ち込むなら経路を示すメッセージが出ます。「laser (printer) takes bdf, but any reaches it: raw → fan → laser」のようにです。ノードの設定だけを変えたときは、先のノードが受け取らないものを運ぶエッジが残っても保存されます。エッジは壊れたまま残り、保存のときにそう知らされます（[壊れたエッジ](flow.md#broken)）。設定の下の 1 行が、そのノードが受け取るもの、いま送れるもの、送り出すものを示します。そこから出る壊れたエッジがあれば、その説明と直し方もそこに出ます。

### 名前・題名・説明 {#names}

ノードの名前は英数字と `.`、`_`、`-`（64 文字まで）で、後から変えられません。ノードの IPP の宛先 `/ipp/print/<name>` であり、アプリケーションやほかのノードが参照するものだからです。題名は名前の下に表示されます。説明はノードが何のためにあるかのメモです。「ERP の請求書。PDF のみ。3 階で印刷」のように、1000 文字まで書けます。C4 図の要素の説明のように、最初の数行がキャンバスのノードの中に、全文がサイドバーに出ます。ディスプレイ、プリンタ、シンク、エクスポートは種類を変えられません。それ以外の種類のノードは、名前を保ったまま、それ以外の種類の間で変えられます。

### ノードのサイドバー {#sidebar}

種類ごとの設定（[ノードの種類](nodes.md)）のほかに、保存済みのノードのサイドバーには次のものがあります。

- IPP の URL と、そこへ送られたジョブ（Admin → Jobs）、そのインボックス（Admin → Inboxes）、そこで待つ配送（Admin → Deliveries）へのリンク。
- エンドポイントなら、入口（アプリケーションが POST する URL）とキー。Rotate key で新しいキーを作り、1 度だけ表示します（[エンドポイント](entries.md#endpoints)）。
- テンプレートノードなら、テンプレート。アップロード、それぞれが引く項目、ファイル、削除です（[テンプレートとデータ](templates.md)）。
- ディスプレイなら、デバイスと最後に見た日時、そして Add a device。1 度きりのコードと QR コードを表示します（[ディスプレイボード](displays.md)）。
- CUPS サーバーノードなら、コンピュータがプリンタを追加する URL と、一覧するコマンド（[CUPS サーバーノード](entries.md#cups)）。
- シンクなら、保持している最新の文書とそのページ。
- エクスポートなら、読み手が取りに来る URL と、そこに一覧されているエントリ（[HTTP (pull)](exports.md)）。
- プレビューのあるプリンタなら、偽プリンタが受け取ったもの（[プリンタ](nodes.md#printer)）。

サイドバー上部の Help で、このマニュアルのそのノードの種類の節が開きます。
