# テンプレートとデータ {#templates-and-data}

テンプレートノードはデータで帳票を埋め、`.bdf` 文書として先へ送ります。アプリケーションが請求書のデータを送ると、プリンタには請求書が届きます。テンプレートはノード自身のものです。

## ノードのテンプレート {#templates}

テンプレートはトポロジーのページで、ノードのサイドバーの「テンプレート」（ID とファイル）からアップロードするか、`PUT /api/nodes/<node>/templates/<id>` にファイルをボディとして送ります（[テンプレート](api.md#templates)）。テンプレートはノードとともにあります。ノードを削除するとテンプレートも消えます。

テンプレートは `bdf fill` が受け取るものです。

| テンプレート | |
|---|---|
| `.bdft` | コンパイル済みのテンプレート。`bdf template compile` で作ります |
| Excel、Word、PowerPoint | セルや本文にタグを書いた Office 文書 |
| PDF フォーム | 入力欄を埋めます |
| pdfme | pdfme のテンプレート（JSON） |
| text | テキストのテンプレート。テキストモードのプリンタ向けです |

サイドバーには各テンプレートの形式、タグが引く項目の数（マウスを重ねると名前）、ファイル、「削除」が並びます。`GET /api/nodes/<node>/templates/<id>` は項目と、テンプレートが持っていればデータのサンプルを返します。送り手が送るデータの出発点になります。

## 埋めるテンプレート {#which}

ノードの `template` が埋めるテンプレートを指します。代わりに `template_from` で、値がテンプレートを指すメタデータのキーを指定できます。`template_from` を `doc-type` にすると、送り手の `X-Meta-Doc-Type: invoice` ヘッダがテンプレート `invoice` を選びます（[メタデータ](flow.md#metadata)）。埋める処理はノードのステップで、配送と同じように行われます。テンプレートがないのは再試行では直らない失敗で、ジョブは `aborted` になり、理由がレグに残ります（[配送](inboxes.md#deliveries)）。

## データ {#data}

データは種類 `data` のペイロードとしてノードに到達します。`accept: data` のアップローダーから（[アップローダー](entries.md#uploaders)）、または API でノード自体に送ってです。JSON や YAML のオブジェクトはそのままデータです。その名前をテンプレートのタグが引きます。レコードの一覧（CSV ファイル、Excel ブックのシート、JSON の配列）には名前が付きます。ノードの `list_name`、なければ拡張子を除いたファイル名です。テンプレートはその名前でレコードを引きます（レコードごとに行を繰り返す表）。`strict` を付けると、テンプレートが引く名前のないデータは、空で埋める代わりに拒否されます。Parquet ファイルはまだテンプレートに埋められません。テンプレートが求めるデータの JSON Schema は、データがそこへ届くアップローダーの OpenAPI 文書に載ります（[OpenAPI](api.md#openapi)）。

埋めた帳票は `.bdf` 文書で、ジョブの新しいペイロードです。ノードの後ろのプリンタ、ディスプレイ、アーカイブがそれを受け取り、ジョブのページはそれをジョブの文書として表示します（[ペイロード](flow.md#payloads)）。
