# トポロジー {#topology}

トポロジーは文書が流れるネットワークです。あらゆる種類のノードと、その間のエッジです。サインインした全員の 1 つのページ、「トポロジー」にあります。役割 topology を持つ人はそこで編集し、それ以外の人は見て、送れるところに印刷します。バーの「管理」も、管理者ページの「トポロジー」タブも、同じページに行きます。

## キャンバス {#canvas}

キャンバスは、管理者が置いた位置にノードを描きます。ノードは白い箱で、役割の色の題名バー、種類のアイコン、名前、その下に `[種類]` と題名、説明の最初の数行があります。

| 役割 | 種類 |
|---|---|
| ソース | エンドポイント、CUPS サーバー |
| 制御フロー | キュー、クラス、インボックス |
| フィルタ | フィルタ |
| 変換 | テンプレート、変換 |
| シンク | ディスプレイ、プリンタ、アーカイブ、シンク、HTTP (pull) |

ポートとエッジは流れるもので色分けされます（[ペイロードの種類](flow.md#kinds)）。青は `.bdf` 文書、緑はデータ、琥珀色は受け取ったままのファイル、シアンは保管されたファイル（インボックスかアーカイブから HTTP (pull) へ）、紫は複数の種類です。まだ型の決まっていないポートは中抜きの破線です。キュー、クラス、フィルタ、インボックスは最初のエッジの種類を受け取ります。赤い破線のエッジは、もうつながっていません（[壊れたエッジ](flow.md#broken)）。エクスポートには外へ向かう破線の矢印があります。一覧したものをアプリケーションや人が取りに来ることを表します。キャンバスの下の凡例が色を説明します。

キャンバスには、自分が見られるジョブ（自分のものと自分のグループのもの。管理者は全員のもの）の動きが流れます。

- 各ノードの数。インボックスに留まった項目、ディスプレイで開いている伝票、プリンタやアーカイブで待つ配送、失敗した配送、エクスポートが一覧しているエントリ、直近 1 時間にそのノードへ到達したジョブです。
- エッジを走る点。直近 10 分のレグです。

背景をドラッグすると移動、ホイールかピンチで拡大縮小、「全体」でトポロジーを表示に収めます。ページは数秒ごとにマネージャーをポーリングします。題名の横のバッジが、動きの最終更新か、マネージャーに届かないことを示します。

## 見る {#view}

役割 topology がなければ、このページは見るだけです。ノードをクリックすると、サイドバーにその説明、そこにある自分のジョブの数、送り先、受け取るものと送り出すもの、そして次のものが出ます。

- **ここで印刷**: そのノードに送れるとき（[ノードのスコープ](roles.md#scopes)）。ファイルとジョブ名を指定します。[ジョブのページ](jobs.md#print)と同じです。送れなければ「ここには印刷できません」と出ます。
- **ここのジョブ**: そのノードに送られたか到達した自分のジョブ。状態、送り手、日時、経路が並びます。「文書」でダウンロードし、「ここで再印刷」でこのノードに自分の新しいジョブとして送り直します。

シンクなら保持している最新の文書、エクスポートならそこに一覧されている自分が読めるエントリ（[HTTP (pull)](exports.md)）、CUPS サーバー（ソース）ならコンピュータにプリンタとして追加する方法（[CUPS サーバーノード](entries.md#cups)）も出ます。

## エディタ {#editor}

役割 topology があれば、同じページがエディタです。キャンバスと、選んだノードのサイドバーがあり、上に管理者のタブが並びます。

- **+ ノードを追加** で種類のパレットが開きます。種類はソース、制御（役割の制御フローとフィルタ）、変換、シンクの 4 つの見出しに分けてあります。1 つ選ぶと新しいノードがキャンバスに現れ、サイドバーが開きます。題名、名前、設定を入れて「追加」を押します。Escape で取りやめます。ノードはエッジがなくても追加できます。どの順に置いてもよく、つなぐのは後ろのノードができてからです。まだどこにも送らない入口、キュー、ステップに届いたジョブは、そこでエラー「sends to no node yet」になり、経路に残ります。
- **ノードをクリック**するとサイドバーに開きます。設定タブで編集し、使い方タブで外からの届き方とそこにあるものを見ます（[ノードのサイドバー](#sidebar)）。「保存」でノードを書き込み、「削除」か Delete キーで削除します。ほかのノードが送り先にしているノードは削除できません。先にエッジを外します。
- **ノードをドラッグ**すると動きます。ノードを描く位置は、ノード自体とは別に、全員のものとして保存されます（レイアウト）。
- **ノードの右側のポートから別のノードへドラッグ**するとつながります。ドラッグ中は、エッジが運ぶものを受け取らないノードが薄くなり、その上では線が赤くなって理由が出ます。受け取るノードではそのポートに吸い付きます。受け取らないノードに落とすと、サーバーに問い合わせる前に拒否されます。エッジはノードの `to`（キュー、エンドポイント、CUPS サーバー、インボックス、テンプレートノード、変換ノード、アーカイブ）、`members`（クラス）、`otherwise`（フィルタ。ルールのノードはルールの中で設定します）に加わるか、フォールバックプリンタになります（ディスプレイ）。ブランチにはケースごとのポートと `default` のポートが、アサートには通ったもの（`to`）と通らなかったもの（`on_error`）のポートがあり、それぞれラベルが付いています。エッジは、ドラッグを始めたポートの枝に加わります。エッジをクリックすると、確認のうえで外せます。
- −（縮小）、全体、+（拡大）、更新。

ノードは保存のときに検査されます。名前で参照するノードが存在すること、名前がほかの種類のものでないこと、ノードへ戻る経路がないこと、新しいエッジが先のノードの受け取らない種類のペイロードを持ち込まないことです。持ち込むなら経路を示すメッセージが出ます。「laser (printer) takes bdf, but any reaches it: raw → fan → laser」のようにです。ノードの設定だけを変えたときは、先のノードが受け取らないものを運ぶエッジが残っても保存されます。エッジは壊れたまま残り、保存のときにそう知らされます（[壊れたエッジ](flow.md#broken)）。設定の下の 1 行が、そのノードが受け取るもの、いま送れるもの、送り出すものを示します。そこから出る壊れたエッジがあれば、その説明と直し方もそこに出ます。

### 名前・題名・説明 {#names}

ノードには題名と名前があります。題名は人が読むもので、どんな文字でも使えます。キャンバスではノードのタイトルバーに出ます（題名がなければ名前）。名前はシステムのためのもので、英数字と `.`、`_`、`-` の 64 文字まで、先頭は英数字で、ほかのノードと重なりません。ほかのノードのエッジ、URL（`/in/<name>`、CUPS サーバーの `/printers/<name>`、`/out/<name>`）、記録がこの名前でノードを指します。「名前」の欄は入力のたびに検査されます。空白やほかの文字、ほかのノードの名前を入れると欄が赤くなり、何がいけないかが下に出て、直すまで保存できません。

保存済みのノードの名前を変えると、確認のうえで、保存のときに名前が変わります。送り元のノードのエッジ、描く位置、その名前で保存しているもの（テンプレートノードのテンプレート、ディスプレイのデバイスとまだ表示している伝票、インボックスのアイテム、シンクの文書、エクスポートのエントリ）が付いてきます。アーカイブは同じコレクションに書き続けます。外からの届き先も変わるので、前の名前で設定したコンピュータやアプリケーションは設定し直します。届いたジョブは前の名前のままです。処理中の仕事があるノード（待っているか失敗した配送、インボックスに留めたアイテム、ディスプレイで開いている伝票）は、それが済んでから名前を変えられます。マネージャーの `docflow.on_error` が指すノードも、設定を新しい名前に変えてからです。

説明はノードが何のためにあるかのメモです。「ERP の請求書。PDF のみ。3 階で印刷」のように、1000 文字まで書けます。C4 図の要素の説明のように、最初の数行がキャンバスのノードの中に、全文がサイドバーに出ます。ディスプレイ、プリンタ、シンク、エクスポートは種類を変えられません。それ以外の種類のノードは、名前を保ったまま、それ以外の種類の間で変えられます。

### ノードのサイドバー {#sidebar}

保存済みのノードのサイドバーには 2 つのタブがあります。選んだタブは、ほかのノードをクリックしてもそのままです。

**設定**: 題名、名前、説明、種類ごとの設定（[ノードの種類](nodes.md)）、スコープと所有者、「保存」と「削除」。テンプレートノードならテンプレートも。アップロード、それぞれが引く項目、ファイル、削除です（[テンプレートとデータ](templates.md)）。

**使い方**: 外からどう届くかと、そこにあるもの。

- CUPS サーバー（ソース）なら、コンピュータがプリンタを追加する URL、macOS・Windows・CUPS での追加のしかた、コマンド（[CUPS サーバーノード](entries.md#cups)）。
- プリンタと CUPS サーバー（シンク）なら、このシステムがジョブを印刷する先。IPP で送ります（プリンタは 9100 や LPD も）（[CUPS サーバー（シンク）](nodes.md#cups-out)）。
- エンドポイントなら、アプリケーションが送るリクエスト、許可したアプリ、キー。「キーを回す」で新しいキーを作り、1 度だけ表示します（[エンドポイント](entries.md#endpoints)）。S3 トリガーなら、S3 のイベントの参照を POST するリクエストとキー。
- ディスプレイなら、デバイスと最後に見た日時、そして「デバイスを追加（QR コード）」。1 度きりのコードと QR コードを表示します（[ディスプレイボード](displays.md)）。
- エクスポートなら、読み手が取りに来る URL と、そこに一覧されているエントリ（[HTTP (pull)](exports.md)）。
- そこへ送られたジョブ（管理 → ジョブ）、そのインボックス（管理 → インボックス）、そこで待つ配送（管理 → 配送）へのリンク。入口とエクスポートなら OpenAPI の文書も。
- シンクなら、保持している最新の文書とそのページ。プレビューのあるプリンタなら、偽プリンタが受け取ったもの（[プリンタ](nodes.md#printer)）。

ほかのノードにはエッジを通ってだけ届き、使い方タブにはリンクが出ます。サイドバー上部の「ヘルプ」で、このマニュアルのそのノードの種類の節が開きます。
