# BDF Docflow {#bdf-docflow}

Docflow は、ソフトウェアで定義する文書のネットワークです。文書は入口から入ります。アプリケーションのエンドポイント、コンピュータが印刷する CUPS サーバー、どのノードにもある IPP プリンタ、Jobs ページのフォームです。そこから、管理者が組み立てたノードを流れます。複数に分岐するキュー、メンバーに順番に送るクラス、ジョブの性質で振り分けるフィルタ、人が送り出すまでジョブを留めるインボックス、データで帳票を埋めるテンプレートノード、ファイルから文書を作る変換ノードです。行き着く先は、ディスプレイボード（拠点に登録したタブレット）、プリンタ、誰も変更できない写しを残すアーカイブ、最新の文書を見るためのシンク、アプリケーションや人が文書を取りに来るエクスポート（HTTP (pull) ノード）です。Web サービスへ送り出すこともできます（HTTP (push)）。紙は行き先の 1 つにすぎません。

## ページ {#pages}

| ページ | 誰が | 何を |
|---|---|---|
| Jobs | サインインした全員 | 送れるノードに文書を印刷する。自分のジョブと自分のグループのジョブ（[ジョブ](jobs.md)） |
| Topology | サインインした全員 | 配置されたとおりのネットワークと、見られるジョブの動き。ノードで印刷する（[見る](topology.md#view)） |
| Topology（エディタ） | 役割 topology | 同じページ。ノードを置き、つなぎ、設定する（[エディタ](topology.md#editor)、[ノードの種類](nodes.md)）。バーの Admin もここに行く |
| Admin → Apps | 役割 topology | 自前の資格情報を持つアプリケーション。送ったり読んだりするバックエンドと、人のブラウザで動くフロントエンド（[アプリ](entries.md#apps)、[フロントエンド](exports.md#frontends)） |
| Admin → Inboxes | 役割 topology | インボックスに留まったものを送り出す、または破棄する（[インボックス](inboxes.md#inboxes)） |
| Admin → Jobs | 役割 topology | すべてのジョブ、または 1 つのノードに送られたジョブと、それぞれがたどった経路 |
| Admin → Deliveries | 役割 topology | プリンタ、アーカイブ、ステップを待つものと、ティック（[配送](inboxes.md#deliveries)） |
| Audit | 役割 audit | 誰が何をしたか（[監査](roles.md#audit)） |
| Help | サインインした全員 | このマニュアル。英語と日本語 |
| `/tablet` | デバイス | 拠点のディスプレイボード。サインインはなく、デバイス自身のキーで入る（[ディスプレイボード](displays.md)） |

管理者はすべての役割を持ちます。誰が入れるか、誰がどの役割を持つかは[サインイン・役割・監査](roles.md)にあります。

## ジョブの流れ {#flow}

ジョブとは、送り手がノードに送ったもの（文書、またはテンプレートのためのデータ）と、それがネットワークをたどる道のりです。マネージャーは文書を 1 つだけ保存し、ジョブが到達したノードごとに *レグ* を残します。そこで何が起きたか（先へ送った、表示した、留めた、印刷した、アーカイブした、失敗した……）です。ジョブの状態はレグから決まります。配送が未完なら `processing`、インボックスが留めていれば `held`、すべてのノードが受け取れば `completed`、取り消されれば `canceled`、配送が最終的に失敗すれば `aborted` です。[状態](jobs.md#states)に一覧があります。ジョブが運ぶものと、ともに流れるメタデータは[流れるもの](flow.md)にあります。

プロセスは何も抱えません。記録と文書はストアにあるので、同じマネージャーが拠点のサーバーで 1 プロセスとして、複数プロセスとして、あるいは関数として動きます。やるべきこと（配送、紙に印刷する伝票、古い記録の削除）は、ジョブの経路が決まった直後と、*ティック* で行います。ティックはプロセスなら 30 秒ごと、スケジューラが呼ぶならそのときです（[ティック](inboxes.md#tick)）。

## どこから読むか {#start}

- **印刷する人。** [ジョブ](jobs.md)。送れるノードは、全員で共有するもの、自分のグループのもの、自分のものです（[スコープ](roles.md#scopes)）。
- **ネットワークを組む人。** [トポロジー](topology.md)、続いて各ノードの設定は[ノードの種類](nodes.md)、何と何をつなげるかは[流れるもの](flow.md)、データから帳票を埋めるなら[テンプレートとデータ](templates.md)、タブレットは[ディスプレイボード](displays.md)です。
- **アプリケーションをつなぐ人。** [文書の入口](entries.md)。エンドポイントとそのキー、アプリとそのトークン、CUPS サーバーノードと IPP。文書を取りに来るアプリケーションや人は[HTTP (pull)](exports.md)。続いて [API](api.md)。
- **サービスを運用する人。** [マネージャーを動かす](operate.md)。
